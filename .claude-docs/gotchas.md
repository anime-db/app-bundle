# Подводные камни — anime-db/app-bundle

## `CommandExecutor::send()` использует сырой сокет, а не HTTP-клиент Symfony

`send()` открывает обычный `fsockopen` на `localhost:80` и отправляет POST, не читая ответ. Это «выстрелил и забыл». Если приложение в момент вызова не работает на порту 80, открытие сокета молча падает (жёстко зашитый таймаут 2 секунды). Не используйте это для команд, которым нужно подтверждение успеха.

## `CommandExecutor::exec()` устарел

`exec()` (в единственном числе) делегирует в `send()` через legacy-обёртку. Используйте `execute()` или `console()`. Его удаление сломает любой код, всё ещё вызывающий старый интерфейс.

## `Task.modify` — это строка, совместимая с `strtotime` PHP, а не cron-выражение

Планировщик сдвигает `next_run`, вызывая `DateTime::modify($this->modify)` в цикле. Корректно: `+1 hour`, `+30 minutes`. Некорректно: cron-синтаксис (`0 * * * *`). Ограничение проверяется в `Task::isModifyValid()` через `@Assert\Callback`.

## `CacheClearer` удаляет путь кэша в стиле Symfony 2 — `app/cache/`

Он удаляет `<kernel.root_dir>/cache/` — это раскладка Symfony 2/3 (`app/cache/`). В Symfony 4+ кэш лежит в `var/cache/`, и этот сервис там ничего не сделает.

## Слушатель `Package` молча подавляет ошибки API при получении метаданных плагина

`try/catch` в `addPackage()` ловит все `\Exception` и продолжает. Если API недоступен, плагин всё равно сохраняется с пустыми title/description/logo. Это сделано намеренно («не критичная ошибка»).

## `CommandExecutor::prepare()` переписывает только команды, начинающиеся с `php ` (с пробелом)

Проверка префикса — `substr($command, 0, 4) == 'php '`, четыре символа включая пробел. У команды, начинающейся с `php5` или `php7`, путь к бинарнику НЕ будет переписан.

## Миграции Doctrine используют имена классов на основе timestamp с суффиксом-описанием

Формат: `Version<ГГГГММДДЧЧММСС>_<Описание>.php`. В `migrations.yml` пространство имён задано как `AnimeDb\Bundle\AppBundle\DoctrineMigrations`, а каталог — `src/DoctrineMigrations`. Если запускать миграции из другого рабочего каталога, путь в `migrations.yml` нужно скорректировать.
