# Операционный контекст — anime-db/app-bundle

> Кто вызывает этот код, в какой модели угроз он живёт, какие легаси-решения приняты осознанно
> и каков их статус. Детали багов — в [../docs/BUGS.md](../docs/BUGS.md); ловушки — в [gotchas.md](gotchas.md).

## Что это и как запускается

`app-bundle` — **библиотека-бандл** (`"type": "library"`), не самостоятельное приложение. Он загружается
внутри host-приложения `anime-db/anime-db` вместе с родственными бандлами (`api-client-bundle`,
`cache-time-keeper-bundle`, опционально `shmop`). В отрыве от них бандл **не загрузится** — в `services.yml`
есть жёсткие DI-ссылки на сервисы host-приложения (`@anime_db.manipulator.composer`,
`@anime_db.manipulator.parameters`, `@anime_db.api.client`, `@anime_db.client`).

Модель развёртывания: приложение для **домашнего использования**. Пользователь запускает его на своём ПК
(Windows или *nix), UI открывает в браузере на `localhost`. Отдельной утилиты-монитора (`anime-db/monitor`,
C++/Qt System Tray) запускает процесс на Windows.

## Кто вызывает код бандла (точки входа)

| Канал                         | Что инициирует                                                                                                                                                                         | Аутентификация   |
|-------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------|
| **HTTP (браузер UI)**         | Маршруты `notice_*`, `form_*`, `media_favicon`, `command_exec` — см. [../docs/PROJECT.md](../docs/PROJECT.md).                                                                         | **Нет** в бандле |
| **CLI-демон**                 | `animedb:task-scheduler` крутит `while(true)`, выбирает задачи из таблицы `task` и запускает их команды в фоне. Запуск демона — **внешний** (нет systemd/supervisor-обёртки в бандле). | n/a              |
| **CLI-команды по расписанию** | `animedb:clear-media-temp`, `animedb:propose-update` — задачи в таблице `task`, заведённые миграциями.                                                                                 | n/a              |
| **Doctrine-события**          | listener `Entity` (`postRemove`/`postUpdate`) удаляет осиротевшие файлы изображений.                                                                                                   | n/a              |
| **События host-приложения**   | listener'ы `Project`/`Package` ловят `anime_db.project.*` / `anime_db.package.*`, которые бросает composer-обёртка host-приложения при install/update/remove.                          | n/a              |
| **Внутренний self-call**      | `CommandExecutor::send()` шлёт raw-POST `fsockopen` на собственный маршрут `command_exec`, чтобы породить фоновый процесс из веб-контекста, не блокируя ответ.                         | **Нет**          |

Ключевой вывод: **бандл не реализует слой аутентификации/авторизации**. Любая защита HTTP-эндпоинтов —
ответственность host-приложения или окружения (firewall, bind на `127.0.0.1`). По умолчанию её может не быть.

## Модель угроз

Приложение задумано как однопользовательское на `localhost`, и многие «дыры» — следствие этого допущения.
Но допущение хрупкое: приложение часто биндится на `0.0.0.0`, доступно из локальной сети и уязвимо к
CSRF/SSRF из браузера пользователя.

| Поверхность                           | Риск                                                                                                            | Статус                                                                                                                 |
|---------------------------------------|-----------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| `command_exec` (`/command/exec.html`) | 🔴 **RCE**: произвольная shell-команда из POST `command`, без auth/CSRF/whitelist. Полная компрометация машины. | Известно, [../docs/BUGS.md](../docs/BUGS.md) #1. **Не расширять**, переработать дизайн.                                |
| `media_favicon` (`host: .+`)          | 🟡 Path traversal записи `.ico` за пределы `web/media/favicon/`; инъекция `host` в Google-прокси URL.           | Известно, BUGS #3. Смягчено: всегда дописывается `.ico`, MIME-проверка, загрузка через Google-прокси (SSRF ограничен). |
| Загрузка изображений форм             | 🟢 Имя файла из `getClientOriginalName()` без санитизации (двойные расширения, омоглифы).                       | Известно, BUGS #5. `pathinfo basename` снимает прямой traversal.                                                       |
| `CommandExecutor::send()`             | Открытый plaintext-POST на `command_exec` — архитектурно эндпоинт открыт для self-call.                         | Связано с RCE; смягчающего фактора нет.                                                                                |
| Доверие к путям ФС                    | favicon host, имена загрузок — пользовательский ввод в путях. См. запрет в корневом CLAUDE.md.                  | Частично смягчено, требует доработки.                                                                                  |

При любой работе с этими местами: **не доверяй пользовательскому вводу в путях и командах**; результат
`findOneBy`/`find` проверяй на `null` (общий паттерн, источник BUGS #2).

## Легаси-решения и их статус

| Решение                                                        | Почему так                                                                                                      | Статус / что делать                                                                                                                                              |
|----------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Стек заморожен на Symfony 2.x / PHP 5.4**                    | Строковые типы форм, передача экземпляров типов, `ContainerAwareCommand`, Guzzle 3 — несовместимы с Symfony 3+. | Осознанно заморожен. **Не апгрейдить «по пути».** Модернизация — отдельная задача, см. [../docs/RECOMMENDATIONS.md](../docs/RECOMMENDATIONS.md).                 |
| **Метаданные `composer.json` расходятся с веткой**             | Декларирует `php >=5.4` и `branch-alias 0.4.x`, активная ветка — `2.x`.                                         | Расхождение известно. Не «выравнивать» без согласования.                                                                                                         |
| **Состояние «пора обновляться» — в mtime `composer.json`**     | `ProposeUpdateCommand` читает `filemtime` и делает `touch()` для сдвига следующего напоминания.                 | 🟢 Хрупко (BUGS #6): любой `composer install/update` сбрасывает mtime. Параметр `last_update` объявлен, но **не используется** — задел под нормальное хранилище. |
| **БД — SQLite, DQL `DATETIME()` SQLite-специфична**            | `DQL/Datetime.php` завязана на синтаксис SQLite.                                                                | Намеренно. При смене СУБД функцию переписывать.                                                                                                                  |
| **`CacheClearer` чистит `app/cache/`** (раскладка Symfony 2/3) | `<kernel.root_dir>/cache/`.                                                                                     | На Symfony 4+ (кэш в `var/cache/`) сервис ничего не сделает. См. [gotchas.md](gotchas.md).                                                                       |
| **Демон планировщика без graceful shutdown**                   | `while(true)` без обработки сигналов; запуск/останов — внешний.                                                 | 🟢 BUGS #7: возможен busy-loop при «убежавшей» задаче. Управление демоном вне бандла.                                                                            |
| **Ошибки API метаданных плагина молча проглатываются**         | `catch (\Exception)` в listener `Package` — «не критичная ошибка».                                              | Намеренно: плагин сохраняется с пустыми title/description/logo.                                                                                                  |
| **Переводы только на русском (`*.ru.xlf`)**                    | Основная локаль проекта — `ru` (en-версии — исключение).                                                        | Намеренно, см. границы в корневом CLAUDE.md.                                                                                                                     |

## Окружение разработки

- `vendor/` обычно **отсутствует**; локальный PHP — **8.3**, на котором стек (PHP 5.4 / Symfony 2 / PHPUnit 4 / Guzzle 3) **не установится и не запустится**.
- Для тестов нужен PHP 5.6/7.x (Docker). Аудит в [../docs/](../docs/) — **статический**, без прогона.
- Тестовый bootstrap (`tests/bootstrap.php`) требует `vendor/autoload.php` → сперва `composer install` на совместимом PHP.
- Прямые коммиты в `docs/*/` корневого воркспейса запрещены — это клоны внешних репозиториев (изменения через `push_docs.sh`). Но **внутри этого репозитория** (`docs/app-bundle/`) правки делаются обычным git.
